# Acceptance Criteria Table
Traditional Chinese Music AI Music Generation System - Acceptance Criteria Table

| No. | Scenario Type | Test Scenario | Evaluation Metric | Threshold + Tolerance | Measurement Method | Failure Handling Measures |
|-----|---------------|---------------|-------------------|----------------------|---------------------|---------------------------|
| 1 | Normal Scenario | User inputs valid emotions, styles, and keywords to generate music normally | Generation Success Rate | 100%, tolerance 0% | Initiate a normal request and check that the returned status=success | Check the model service and input parsing logic, then regenerate |
| 2 | Normal Scenario | Generated MIDI is playable, and sheet music images are accessible | Output Usability | 100% available, tolerance 0% | Download and play MIDI, open image links | Check the file storage service and regenerate output files |
| 3 | Boundary Scenario | User inputs only 1 keyword with other parameters as default | Input Compatibility | Generate normally without errors | Submit the minimum valid input and observe system behavior | Optimize the input default value logic to ensure stability for boundary inputs |
| 4 | Boundary Scenario | User sets music duration to 60 seconds (maximum value) | Duration Accuracy | Actual generated duration = 60 seconds, tolerance ±1 second | Check the output duration_sec field | Limit the maximum duration and fix the model generation logic |
| 5 | Boundary Scenario | User reaches the daily free generation limit | Rate Limiting Effectiveness | Trigger the count limit and return the correct prompt | Generate 5 times consecutively and test if the 6th attempt is blocked | Optimize the counting logic to ensure accurate user quota |
| 6 | Degradation Scenario | Generation times out (>12 seconds), triggering degradation | Degradation Success Rate | 100% return degraded music, tolerance 0% | Simulate a timeout and check that status=degraded | Optimize timeout judgment to ensure stable degradation logic |
| 7 | Degradation Scenario | User inputs ambiguous emotions (both cheerful and sad) | Automatic Processing Accuracy | 100% automatic selection of calm emotion | Submit ambiguous emotions and check the output emotion_detected | Optimize emotion parsing rules to improve processing capability for ambiguous inputs |
| 8 | Negative Scenario | User submits empty input (no emotion, style, or keyword) | Parameter Validation | Reject directly and return 400 error | Submit an empty request and check the error code | Strengthen front-end/interface validation to prohibit empty requests from entering the system |
| 9 | Negative Scenario | User inputs invalid keywords (abc123, special symbols) | Keyword Filtering | Ignore invalid words without affecting generation | Submit invalid keywords and check if generation proceeds normally | Optimize keyword cleaning logic to filter illegal characters |
| 10 | Negative Scenario | User sends high-frequency requests, triggering per-minute rate limiting | Rate Limiting Rules | 100% return 429 status code | Initiate 6 consecutive requests within 1 second | Adjust rate limiting thresholds and optimize anti-attack mechanisms |
